Overview

Easy Notes is a mobile-first app to keep notes and documents (PDFs and photos) organised in folders. It is a Progressive Web App built with React 19, Vite and Tailwind CSS 4. All data stays in the browser (IndexedDB) on the user's device: there is no server, no account, no tracking and no external requests.

Because it is a set of static files, you can host it for free on any static host and it keeps working offline.

Features

  • Folders & sub-foldersAny depth; Notes and Documents each have their own folders.
  • NotesAutosave, search, sort, pin to top, share, print / save as PDF.
  • DocumentsUpload PDFs and images or take a photo; PDFs preview inside the app on every device.
  • Move & organiseMove notes, documents and folders between folders.
  • Trash with UndoDeleted items can be restored for 30 days.
  • Backup & restoreOne JSON file with everything, including the documents.
  • Sample data“Try with sample data” on the Welcome screen, plus “Load sample data” and “Delete all data” in Settings.
  • Offline & installableService worker and web manifest; install on phone or desktop.
  • Light & dark modeFollows the system, with a switch in Settings.
  • AccessibleKeyboard friendly, visible focus, labelled buttons; checked with axe-core in light and dark mode.

Requirements

  • Node.js 20 or newer (includes npm).
  • Any code editor (for example VS Code).
  • No database, server or API keys are needed.

Install & run

Open a terminal in the project folder and run:

npm install       # install dependencies (first time only)
npm run dev       # start the dev server at http://localhost:5173
npm run build     # production build into the dist/ folder
npm run preview   # serve the production build at http://localhost:4173

Quality checks

npm run lint      # ESLint
npm test          # unit tests (Vitest)
npm run check     # lint + unit tests + build (the same as CI)
npm run test:e2e  # browser tests in Chromium, Firefox and WebKit (Playwright)

Before the first npm run test:e2e, install the test browsers once with npx playwright install.

How data is stored

Everything is stored in the browser's IndexedDB database easy-notes:

StoreContents
folders{ id, name, kind: "note" | "doc", parentId, createdAt, deletedAt? }
notes{ id, title, body, pinned, folderId, createdAt, updatedAt, deletedAt? }
docs{ id, name, type, size, pinned, folderId, createdAt, deletedAt? }
filesThe PDF / image file of each document, keyed by the document's id.
  • Only records that changed are written. Each batch of changes is also kept in a small journal in localStorage until IndexedDB confirms it, so closing the app while typing never loses text.
  • Items in the Trash keep a deletedAt time and are removed for good after 30 days.
  • Small settings (name entered on the Welcome screen, theme, last backup time) are in localStorage with the prefix easy_notes_.
  • Backups are JSON files ("app": "easy-notes", "version") with all records; documents are included as base64 data URLs. Restoring validates every record and only accepts PDFs and images.

Browsers may clear website data (for example when a phone runs out of space). Tell your users to use Settings → Download backup regularly; the app also asks the browser for persistent storage.

Change the app name

Search the project for Easy Notes and replace it. The places users see are:

  • index.html — <title>, apple-mobile-web-app-title and the start-up error text.
  • vite.config.js — manifest.name, short_name (max ~12 characters, shown under the home-screen icon) and description.
  • src/screens/Welcome.jsx and src/screens/Home.jsx — the heading.
  • src/screens/LoadingScreen.jsx, src/screens/Settings.jsx, src/lib/backup.js — messages.
  • package.json — name (lowercase, no spaces).

Do not change DB_NAME in src/lib/db.js, the easy_notes_ keys or APP in backup.js after people have started using your app — their existing data and backups would no longer be found. For a brand-new app you can rename them freely.

Colours & fonts

The design uses Tailwind's built-in palettes: indigo for the brand colour and slate for text, backgrounds and borders (with amber for folders and pins, rose for delete actions).

Change the brand colour in one place

In Tailwind 4 you can redefine a palette in src/index.css. For example, to turn the indigo accent green:

@theme {
  --font-sans: "Inter Variable", "Inter", ui-sans-serif, system-ui, sans-serif;

  --color-indigo-50:  #ecfdf5;
  --color-indigo-100: #d1fae5;
  --color-indigo-300: #6ee7b7;
  --color-indigo-400: #34d399;
  --color-indigo-500: #10b981;
  --color-indigo-600: #047857;
  --color-indigo-700: #065f46;
}

Then also update theme_color in vite.config.js and the button colour in the start-up fallback in index.html. Keep text contrast at 4.5:1 or more (run npm run test:e2e; the accessibility tests check this in light and dark mode).

Dark mode

Dark mode uses a .dark class on <html> (see @custom-variant dark in index.css). Every colour has a dark: variant next to it in the components.

Font

Inter is bundled with the app through @fontsource-variable/inter (no Google Fonts request). To use another font, install its Fontsource package, import it in src/main.jsx and change --font-sans.

Icons & PWA manifest

  • App icons are in public/: icon.svg (browser tab), icon-192.png, icon-512.png, icon-maskable-512.png (Android, with safe padding) and apple-touch-icon.png (180×180, iPhone/iPad). Replace them with files of the same names and sizes.
  • Manifest (name, colours, icons, start URL) is set in vite.config.js under VitePWA({ manifest }). start_url and scope are ./ so the app works in a sub-folder (like GitHub Pages).
  • Interface icons come from lucide-react; import any other icon by name, e.g. import { Star } from "lucide-react".
  • Updates: the service worker updates automatically; UpdateNotifier tells the user when a new version is ready.

Sample data

“Try with sample data” (Welcome screen) and “Load sample data” (Settings) add fictional folders, nine notes and six small documents. The PDFs and PNGs are generated in code (src/lib/sampleFiles.js), so no extra files ship with the app. Sample items are normal items: they can be edited, moved, deleted, backed up and restored. Edit src/lib/sampleData.js to change the content. “Delete all data” in Settings removes everything, including the Trash, after a confirmation.

Deploy

Run npm run build and upload the contents of dist/ to any static host — Netlify, Vercel, Cloudflare Pages, GitHub Pages, Firebase Hosting or a normal web server. No server configuration is needed: the app uses relative paths and hash URLs (#/notes), so it works at the root of a domain or in a sub-folder.

Serve the site over HTTPS (or localhost). Browsers only enable the service worker, offline mode and “install app” on secure origins.

GitHub Pages (included)

  1. Push the project to a GitHub repository.
  2. In the repository open Settings → Pages and set Source to GitHub Actions.
  3. Every push to main runs .github/workflows/deploy.yml: it runs lint, unit tests and the build, then publishes dist/. The address is shown in the workflow run, usually https://<user>.github.io/<repository>/.

.github/workflows/ci.yml runs the same checks plus the Playwright browser tests on every pull request.

Connect a backend (optional)

The app works fully without a server. If you later want accounts or sync between devices, all storage goes through a small set of functions in src/lib/db.js:

FunctionWhat it does
loadAll()Returns { notes, docs, folders } at start-up.
writeChanges(changes)Saves changed records: { notes: { put: [], del: [] }, docs: …, folders: … }.
putFile(id, blob) / getFile(id) / deleteFile(id)Stores, reads and deletes a document's file.

A simple path is to keep IndexedDB as the local copy and add a sync step, or to implement the same functions with fetch() calls to your API (for example a REST API, Supabase or Firebase). Things to add when you do this:

  • User sign-in, and server-side checks so each user can only read and write their own records.
  • File uploads to object storage with size and type limits (the app allows PDFs and images up to 25 MB).
  • An updatedAt on every record so you can resolve edits made on two devices.
  • Update the privacy text on the Welcome screen, which currently says data stays on the device.

Browser support

Current versions of Chrome, Edge, Firefox and Safari on desktop, Android and iOS / iPadOS. Tailwind CSS 4 needs roughly Chrome / Edge 111+, Safari 16.4+ and Firefox 128+. The app is tested automatically in Chromium, Firefox and WebKit (Safari's engine).

In private / incognito windows browsers keep data only until the window is closed. Safari's private mode doesn't allow files in IndexedDB, so the app stores document bytes in a compatible format there automatically.

Tests

  • Unit tests (src/lib/__tests__, Vitest): storage, persistence journal, folders, Trash, backup format, sample data and delete-all.
  • Browser tests (e2e/, Playwright): the full user journey (sample data, notes, documents, PDF preview, move, delete / undo, Trash, backup, delete all, restore, dark mode, offline), keyboard focus, and axe-core accessibility checks on every screen and dialog in light and dark mode at 360–1440 px wide.
